Cross-Validation

Validation Set Approach

When we build a “rule” to make predictions, whether we use a traditional approach like a linear model from the “data modeling” culture or an approach such as CART from the “algorithmic” culture, we wish to know if the rule we have will do a good job in predicting future outcomes. The validation set approach considers this problem by dividing a data set into two random pieces, typically (but not always) of the same size. One of this pieces is called the training set and is used to build a model or prediction rule, and the other piece is held out and used afterwords as the test set for validating the model. The hope is that your model/rule will accurately predict values from the test set, yielding a low \(MSE\) (or a high accuracy/low error rate in the case of classification).

For example, the R package MASS has two data sets called Pima.tr and Pima.te that we have already considered. It turns out that the complete data set, dealing with incidence of Type II diabetes among women on the Pima reservation, had \(n=532\) cases, and Pima.tr is a random selected set of \(n=200\) of these cases. The Pima.te set contains the remaining \(n=332\) cases.

We will use Pima.tr as the training set and Pima.te as the test set for the model \[\text{bmi} \sim \text{age+bp+npreg}\] where we try to predict the woman’s body mass index based on her age, her diastolic blood pressure, and the number of pregnancies that she has had. I’ll use linear regression and CART as a comparison of the two cultures; often in the machine learning world people will try many methods as accurate prediction is the main goal, with interpretation or statistical inference as lesser goals (or possibly not cared about at all).

require(tidyverse)
require(MASS)
data(Pima.tr)
data(Pima.te)
# build the linear regression "rule" with the training set
bmi.linreg <- lm(bmi ~ age + bp + npreg,data=Pima.tr)
summary(bmi.linreg)

Notice the \(MSE=48.58372\) when I used multiple linear regression, and it is \(MSE=47.01216\) when I used a regression tree (CART). Since lower values of \(MSE\) are preferred, the CART model seems a good choice.

There are several flaws to this approach, including:

  1. Maybe we don’t have enough data to be able to divide the data set into two pieces of a reasonable size.

  2. Statistical methods tend to “perform worse” (large residuals in regression, errors in classification, etc.) wih smaller data sets, and the validation set approach by definition reduces our sample size.

  3. There can be a lot of variance in our results based on what portion of the original data set is randomly allocated to the training set versus the test set.

Leave-One-Out Cross-Validation (LOOCV)

For the reasons given above, it is often desirable to avoid splitting our data set into two pieces and instead to use each of the cases in our data set in both the training (i.e. building the model or rule) and testing (i.e. making predictions, validating if these predictions are decent) portions. Cross-validation is an approach that tried to compute this error without needing to use precious data to form a validation set with a training set and separate testing set. Clever methodology for accomplishing this task dates back to the 1970s, and recent interest in computer-intensive prediction algorithms, including methods of machine learning, reawakened interest in cross-validation. As noted by Bradley Efron and Trevor Hastie:

cross-valiation is a strongly frequentist procedure.

An attractive approach, which will remind you of the jackknife, is the Leave-One-Out Cross-Validation (LOOCV) approach.

In the LOOCV approach, each individual case takes its turn being the test set for model validation, with the other \(n-1\) points serving as the training set. For example, if we leave out point \(i=1\), then the model/rule is built using points \(i=2,3,\cdots,n\). Then a prediction \(\hat{Y}_{(i)}\) is made for point \(i\) using that rule, and the mean square error \(MSE_i = (Y_i - \hat{Y}_{(i)})^2\) is computed.

This is repeated \(n\) times, with every point taking its turn being “left out”. Once this is done, the LOOCV estimate of \(MSE\) is computed as the average of all \(MSE_i\).

\[CV_{(n)} = \frac{\sum_{i=1}^n MSE_I}{n}\] An amazing fact is that for the special case of linear regression, this turns out to be no more computationally expensive than fitting a single regression model! It is possible to compute the cross-validation \(MSE\) with the formula \[CV_{n}=\frac{1}{n} \sum_{i=1}^n (\frac{Y_i-\hat{Y}_i}{1-hi})^2\] where \(h_i\) is the leverage of data point \(i\) in the regression model, which can be computed with \[h_i=\frac{1}{n} + \frac{(x_i-\bar{x})^2}{\sum_{j=1}^n (x_j -\bar{X})^2}\] for simple linear regression. The leverage \(h_i\) takes on a value from \(1/n\) to 1, increasing as \(x_i\) is further from \(\bar{x}\). These “high leverage” points have a greater impact on the estimated regression model and are thus weighted more heavily in computing the cross-validated \(MSE\). (do we want to find the theory and work through why this works?)

For multiple regression, the leverages are computed with the matrix equation

\[\textbf{H}=\textbf{X}(\textbf{X}^T \textbf{X})^{-1} \textbf{X}^T\] where \[\hat{\textbf{Y}} = \textbf{HY}\]

\(k\)-Fold Cross-Validation (kFCV)

Unfortunately methods other than linear regression don’t lead to such a computationally convenient result, and thus LOOCV can be extremeley time-consuming, as we are forced to refit the model \(n\) times. Thus, it is common to instead use what is known as \(k\)-fold cross-validation. In \(kFCV\), the data set is randomly divided into \(k\) groups (“folds”) of approximately equal size. Let’s take \(k=10\), a very common choice for the number of folds.

Instead of refitting the model \(n\) times, we will refit the model \(k\) times. The first time, we hold out the first fold (the “test” fold), fit/train the model with the other \(k-1\) folds, and then use the test fold to make predictions and compute the MSE using all points in that fold. We repeat this, with each fold taking its turn as the “test” fold. Finally, an estimate of the \(MSE\) is computed: \[CV_{(k)} = \frac{1}{k} \sum_{i=1}^k MSE_i\] In addition to less computational time, there is also a trade-ff between bias and variance which makes \(k\)-fold \(CV\) attractive.

In the validation set approach, where we divide the data set into 2 roughly equal pieces (which is essentially \(k=2\)-fold cross-validation), we will have bias since we will overestimate the \(MSE\) or test error rate.

Conversely, in leave-one-out cross-validation (which is \(n\)-fold), we will have an approximately unbiased estimate of \(MSE\) or test error rate, but at the price of very high variance.

So, if we pick some value of \(k\) between 2 and \(n\), we can lower this variance, at the price of some bias. Empirically, \(k=5\) and \(k=10\) have been found to be good choices.

Cross-Validation for Classification Problems

When we have a classification problem (i.e. the response variable \(Y\) is categorical), then instead of computing a cross-validation estimate of \(MSE\), we instead will compute a estimate of the error rate (i.e. how often values are misclassified). For LOOCV, we get

\[CV_{(n)} = \frac{1}{n} \sum_{i=1}^n Err_i\] where \[Err_i = I(y_i \neq \hat{y}_i)\] Basically, the indicator function is used to set \(Err_i\) equal to 1 when the point is misclassified and equal to 0 when it is correctly classified. The same idea is used if you use \(k\)-fold \(CV\) instead.

Confusion Matrix Metrics

In the special case of a binary response variable (such as either having or not having Type II diabetes), a \(2 \times 2\) confusion matrix which tabulates the actual values of the binary response variable \(Y\) with the classifications \(\hat{Y}\) from the training rule is obtained. Many different statistics can be computed from a confusion matrix.

An example is given below, where the confusion matrix is computed for a logistic regression model that predicts whether a patient has or doesn’t have Type II diabetes, using the Pima.tr data set for training and Pima.te for testing (i.e. the validation set or \(2\)-fold approach.)

require(tidyverse)
require(MASS)
diabetes.model <- glm(type~.,data=Pima.tr,family=binomial(link="logit"))
yprob <- predict(diabetes.model,newdata=Pima.te,type="response")
yhat <- factor(ifelse(yprob>0.5,"Yes","No"))
y <- Pima.te$type
caret::confusionMatrix(yhat,y)

The accuracy is merely the proportion of correct classifications, which is the sum of the main diagonal divided by the total sample size.

Here \[Accuracy = \frac{TN+TP}{TN+TP+FN+FP}=\frac{200+66}{200+66+43+23}=\frac{266}{332}=0.8012\] where \(TN\) is true negatives (the upper left hand corner in this table), \(TP\) is true positives (lower right hand corner), \(FN\) is false negatives (upper right), and \(FP\) is false positives (lower left). The confusionMatrix functon in the caret package orients the confusion matrix with the predictions as rows and actual truth as columns–you will often see this reversed, along with the Yes/Positive and No/Negative reversed, so be cautious!

The error rate is of course just \(1-Accuracy\), so it is 0.1988 in this matrix.

Cohen’s Kappa is a common statistic in the social sciences for measuring inter-rater reliability between two raters, and is used here with one “rater” being the training rule and the other “rater” being the actual truth.

\[\kappa = \frac{p_o-p_e}{1-p_e}\] where \(p_o\) is the observed agreement between the training rule and truth (we called it Accuracy) and \(p_e\) is the expected agreement due to random chance.

In this problem, \(p_o = 0.8012\) and \[p_e = p_{No} + p_{Yes}\] \[p_{No}=\frac{TN+FN}{n} \times \frac{TN+FP}{n} = \frac{243}{332} \times \frac{223}{332}=0.4916\] \[p_{Yes}= \frac{TP+FP}{n} \times {TP+FN}{n} = \frac{89}{332} \times{109}{332} = 0.0880\]

\[p_e = 0.4916 + 0.0880 = 0.5796\]

\[\kappa = \frac{.8012-.5796}{1-.5796} = 0.5271\]

Receiver Operating Characteristic Curve

In the words of Ben Baumer, Danny Kaplan, and Nick Horton:

a more principled approach to assessing the quality of a classifier is a receiver operating characteristic (\(ROC\)) curve. This consiers all possible thresholds for rounding, and graphically displays the trade-off between sensitivity (the true positive rate) and specificity (the true negative rate). What is actually plotted is the true positive rate as a function of the false positive rate.

The area under the \(ROC\) curve, \(AUC\) represents a probability that the model/classifier, if give a random positive example (in this example, someone with diabetes) and a random negative example (someone without diabetes), will rank the positive example higher than the negative example. \(AUC=1\) represents perfect classification, with \(AUC=0.5\) chance-level classification.

I am using the performance package to compute and graph the \(ROC\) curve and \(AUC\) of our logistic regression model. This can be done with many other packages.

# maybe replace with yardstick package, roc_curve and roc_auc
# that is in Chapter 10 of Modern Data Science With R
# https://mdsr-book.github.io/mdsr3e/10-modeling.html
require(performance)
require(see)
plot(performance_roc(diabetes.model)) #ROC curve
performance_accuracy(diabetes.model) #AUC

The caret Package

Max Kuhn’s caret package (classification and regression training) package also gives us the ability to compare literally dozens of methods from both classical statistics and machine learning via \(LOOCV\) or \(k\)-fold cross-validation. I frankly don’t know and have never implemented most of these methods.

Here’s his book on it.

https://topepo.github.io/caret/index.html

I’m going to use his package to show how to implement cross-validation in both a regression (continuous response) and classification (categorical response) setting.

With a continuous response, the most common measure of prediction error is the root-mean-square-error or \(RMSE\).

\[RMSE(y,\hat{y}) = \sqrt{\frac{1}{n}\sum_{i=1}^n (y-\hat{y})^2}\]

Another common measure is mean absolute error \(MAE\) which will not penalize large residuals (“misses”) as heavily since an absolute value is used in place of the squared term.

\[MAE(y,\hat{y}) = \sqrt{\frac{1}{n}\sum_{i=1}^n |y-\hat{y}|}\]

The coefficient of determination, \(R^2\) is the proportion of variability in the outcome explained by the model. When fitting a linear regression model, this is just the ratio of the sum of squares regression to the sum of squares total. \(R^2\) will be on the scale \([0,1]\) with \(R^2=1\) meaning a perfect match between \(y\) and \(\hat{y}\).

The kernlab package is just for the spam data set from the books, as the ElemStatLearn package is no longer available on CRAN.

require(tidyverse)
require(MASS)
require(caret)

## Regression Setting, compare multiple linear regression (lm) with CART (rpart)
## use complete Pima data set Pima.tr2

# set up Leave-One-Out CV 
train_controlLOOCV <- trainControl(method="LOOCV", 
                                  classProbs=FALSE)

# train the model using linear regression
model.linreg <- train(bmi~.,
                    data=na.omit(Pima.tr2),
                    trControl=train_controlLOOCV,
                    method="lm")
print(model.linreg)

Since we would wish to minimize RMSE, the slightly lower value for the CART model is desirable, although you then get to dig into what the cp (model complexity) tuning parameter means. Let’s try for a classification problem, comparing logistic regression and CART for the spam vs ham example (i.e. is an email legitimate or spam)?
